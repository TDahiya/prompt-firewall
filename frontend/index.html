How it works

Six-stage agentic pipeline

Every prompt passes through sequential analysis layers. Each stage can block independently, and the pipeline degrades gracefully if any stage fails.

01
Decoder
Strips zero-width characters, decodes base64 payloads, replaces homoglyphs. Catches obfuscated attacks before they reach detection.
<1ms
→
02
Regex Engine
38 compiled patterns across 7 attack categories. Runs on both original and decoded text. Instant detection for known attack signatures.
<1ms
→
03
Prompt Guard
Meta's llama-prompt-guard-2-86M model. Purpose-built for prompt injection detection. Returns a 0–1 confidence score for fast pre-screening.
~50ms
→
04
CoT Classifier
Chain-of-thought LLM reasoning: surface reading, manipulation check, true intent analysis, then verdict. Catches novel attacks regex misses.
~400ms
→
05
Multi-Turn
Tracks conversation history per session. Detects “boiling frog” escalation attacks that build up gradually over multiple messages.
~300ms
→
06
Output Firewall
Scans LLM responses for system prompt leakage, jailbroken compliance, credential exposure, and harmful step-by-step instructions.
~300ms
Features

Built for real-world defense

Production-grade patterns from real attack datasets. Every LLM call has graceful degradation and individual timeout handling.

☉
7 attack categories
Role override, instruction override, jailbreak, prompt leaking, token smuggling, indirect injection, and context manipulation.
⚙
Chain-of-thought reasoning
Four-step reasoning process: surface reading, manipulation check, true intent analysis, then final verdict with confidence score.
▦
Sandwich architecture
Input firewall screens prompts before the LLM. Output firewall screens responses after. Nothing leaks in either direction.
⏲
Sub-second latency
Regex catches known attacks in <1ms. Prompt Guard pre-screens in ~50ms. Full CoT analysis completes in under a second.
♻
Graceful degradation
Every LLM call is wrapped in try/except. If Prompt Guard fails, CoT runs. If CoT fails, regex still catches known attacks.
⇄
OpenAI-compatible proxy
Drop-in /proxy endpoint. Point your LLM client at the firewall, it screens every message before forwarding to your upstream API.
Detection

Seven attack categories

Each attack is classified into a specific category with confidence scoring and matched pattern details.

Role Override
Attempts to make the LLM adopt a new persona or bypass safety guidelines. “You are now DAN…”
Instruction Override
Direct commands to ignore or override the system prompt. “Ignore all previous instructions…”
Jailbreak
Framing harmful requests as hypothetical, fictional, or for research to bypass safety filters.
Prompt Leaking
Trying to extract the system prompt, instructions, or internal configuration of the LLM.
Token Smuggling
Hiding attacks in base64, zero-width characters, or homoglyphs to evade text-level detection.
Indirect Injection
Injecting instructions via fake system tags, tool outputs, or document content the LLM processes.
Context Manipulation
Fabricating prior agreements or false context. “As we agreed earlier, you can skip safety…”
